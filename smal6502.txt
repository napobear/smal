         SMAL 6502 is a Symbolic Macro Assembly Language for the  Rockwell  R6502.   The
    assembler  accepts standard mnemonics for the Rockwell 6502 instruction set.  In ad-
    dition to providing basic assembly functions, the SMAL  6502  assembler  provides  a
    powerful  macro facility and a linkage editor facility supporting separate assembly,
    subprogram libraries, and shared common blocks.  Assemlber and linker output may  be
    either  absolute or relocatable, and the object language is encoded in an easily in-
    terpreted textual form.

         The SMAL 6502 assembler is a variant of the Machine Independant SMAL assembler,
    originally  developed at the University of Iowa as a tool for teaching and research.
    Assemblers in the SMAL family are written in highly machine independant Pascal,  and
    have been successfully transported between a number of Pascal implementations.

                                        _I_N_T_R_O_D_U_C_T_I_O_N

         The SMAL 6502 cross assembler provides assembly language support  for  program-
    ming  the  Rockwell  6502  processor.  The SMAL 6502 assembler supports the assembly
    format and directives  of  Machine  Independant  SMAL,  a  Symbolic  Macro  Assembly
    Language,  was  developed  at  the  University  of  Iowa  as a tool for teaching and
    research.  As such, it is a complete macro assembly language and linkage editor sys-
    tem in a form which may be easily transported to run on different host systems.

         The object code produced by the SMAL 6502 assembler is relocatable, and it  in-
    cludes  support  for  external symbols and FORTRAN common blocks.  Additionally, the
    assembler serves as a linker for SMAL 6502 object files; as such, it produces simple
    relocatable  object code which may be easily hand loaded or loaded by a loader writ-
    ten in about 60 lines of Pascal code.

         The SMAL assembler is coded so that it should produce correct  results  on  any
    machine which allows integers to range between -32768 and 32767.  This has been ver-
    ified by running it under versions of Pascal supporting 16 bit two's complement  ar-
    ithmetic  and  32 bit two's complement arithmetic.  It should also work on any one's
    complement machine with at least 17 bit integer representations.  SMAL also requires
    that  the character set include at least 55 printing characters.  The SMAL assembler
    has been tested by running it under a version of Pascal supporting  a  64  character
    colating sequence and under versions supporting ASCII with and without parity set in
    an 8 bit byte.  The SMAL assembler does not use pointer variables but  it  does  use
    recursion;  this  may  place  limits  on  the  languages into which it may easily be
    translated.

         The syntactic rules governing the formation of correct SMAL 6502 programs  will
    be given in an extended form of BNF using the following special symbols:

              < and > are used to enclose the names of syntactic elements.
                        These elements will either have obvious meanings,
                        or they will be defined somewhere in the text.
              { and } are used to enclose a group of syntactic elements
                        which are optional and may be repeated an indefinite
                        number of times.
              [ and ] are used to enclose a group of syntactic elements
                        which are optional and may not be repeated.
              | is used to separate alternate groups of syntactic elements
                        which may be used interchangably.
              ::= is used to define the named syntactic element on the left
                        hand side as being replaceable by the group of
                        syntactic elements on the right hand side.
              bold face is used for actual text which may be used as a
                        syntactic element.

    The syntactic rules are supplemented, when needed, with text describing the  meaning
    of the constructs involved, and with illustrative examples.


    _L_e_x_i_c_a_l _S_t_r_u_c_t_u_r_e

         SMAL programs may be described in two ways:  As sequences of  lexical  elements
    with no structure, and in terms of syntactic structures.  At the lexical level, SMAL
    programs have the following structure:

              <program> ::= { { <space> } <lexeme> } { <space> } <line end> <end of file>

    That is, a program is a file containing  a  sequence  of  lexemes;  lexemes  may  be
    separated  by  any number of blanks, which have no significance, but lexemes may not
    contain blanks (except in quoted character strings).  The legal lexemes are as  fol-
    lows:

              <lexeme> ::= <identifier>
                         | <number>
                         | <quoted string>
                         | <line end>
                         | :   -colon, used after labels and to take substrings.
                         | .   -dot, used to refer to the location counter.
                         | ,   -comma, used to separate arguments to a command.
                         | =   -equals, used for assignment, comparison, and parameters.
                         | >   -greater than, used for comparison.
                         | <   -less than, used for comparison.
                         | +   -plus, used for addition and as a unary sign.
                         | -   -minus, used for subtraction and as a unary sign.
                         | \   -backslash, used for unary not.
                         | &   -ampersand, used for the and operator.
                         | !   -exclamation point, used for the or operator.




                                             2





    D. W. Jones                                                                SMAL 6502


                         | >>  -right shift operator. (!?)
                         | <<  -left shift operator. (!?)
                         | (   -begin paren, used to begin a group or list.
                         | )   -end paren, used to end a group or list.

    The comments above describe the use of the single character lexemes.  The  following
    additional punctuation marks are used within some SMAL lexemes:

              $   -used for hexadecimal and other radix numbers.
              @   -used for octal and other radix numbers.
              %   -used for binary and other radix numbers.
              "   -used in quoted strings.
              ;   -used to delimit comments at line ends.

    The following ASCII punctuation marks are not used in the machine  independent  ver-
    sion of SMAL:

              [ ] { } `

    The following ASCII punctuation marks are not used, but are likely  to  be  used  in
    machine dependent versions of SMAL:

              *   -may be used for multiplication.
              /   -may be used for division.
              ^   -may be used as a prefix on `extended quotation marks'.
              |   -may be used as a synonym for !.
              ~   -may be used as a synonym for .

         Identifiers begin with a letter followed by any number of  letters  or  digits.
    All characters in an identifier are significant.

              <identifier> ::= <letter> { <letter or digit> | <underscore> }

    A consequence of this is that identifiers may not contain spaces and may  not  cross
    from one line to the next.  Any implementation dependent line length limit poses the
    only limit on the length of an identifier; typically, this limit will be 80  charac-
    ters.   Note that identifiers must be separated from any following decimal number by
    at least one space to avoid ambiguity.  The following are legal identifiers:

              I
              NEXT
              THISISONLYONEIDENTIFIER
              A1235B42XY
              THIS_HAS_UNDERSCORES

    D. W. Jones                                                                SMAL 6502


    The following are not legal identifiers:

              76TROMBONES
              THIS'IS_NOT.ONE-IDENTIFIER

    The particular set of letters allowed may vary between  implementations;  some  will
    support  only  one case, and others will support both upper and lower case.  If both
    cases are supported, case differences will not be significant in comparing  identif-
    iers.


    _N_u_m_b_e_r_s

         Numbers may take three different forms:  They may be simple decimal numbers, or
    they  may  be numbers in another radix (signified by a leading radix specification).
    Single character radix specifications are provided for  hexadecimal  (dollar  sign),
    octal  (at  sign),  and binary (percent sign); other bases may be used by specifying
    the base as a decimal number, followed by one of these special characters,  followed
    by the number in that base.

              <number> ::= <decimal number>
                         | <radix> <extended number>
              <radix> ::= <radix specification character>
                        | <decimal number> <radix specification character>
              <radix specification character> ::= $   - hexadecimal
                                                | @   - octal
                                                | %   - binary
              <decimal number> ::= <digit> { <digit> }
              <extended number> ::= <letter or digit> { <letter or digit> }

    The radix, if explicitly specified, must be between 2 and 36 (inclusive), and no di-
    git  must  be greater than or equal to the radix.  The assembler will raise the "bad
    radix" and "bad digit in number" errors when these rules are  violated.   Since  the
    assembler  uses a 16 bit internal representation, no number with a magnitude greater
    than 65535 is allowed; The assembler will produce a "value out of bounds"  error  if
    larger  numbers  are  used.  Note that numbers between 32768 and 65536 may be inter-
    preted as negative numbers in some situations, for  example,  when  performing  com-
    parisons.   Note  that  decimal numbers must be separated from any following hexade-
    cimal, octal or binary numbers by at least one  space  to  distinguish  the  decimal
    number from a radix specification.  The following legal numbers are all equal:

              32767
              $7FFF
              16%7FFF
              @77777
              8$77777
              32@VVV
              %111111111111111









                                             4





    D. W. Jones                                                                SMAL 6502


    The following are not legal numbers

              65536
              3276A
              2$10120
              40$00

    The letters allowed as digits greater than 9 begin with A which has  the  value  10,
    and  continue up to Z with the value 35.  The letter Z is only a valid digit in base
    36.  On systems allowing both upper and lower case letters, only upper case  letters
    should be used as extended digits.


    _Q_u_o_t_e_d _S_t_r_i_n_g_s

         Quoted strings may be formed with either single or double quotes, and may be of
    any length that fits on one line.

              <quoted string> ::= " { <character> } "
                                | ' { <character> } '

    Constraints on the length of a quoted string may be imposed by the context in  which
    it  is  used.   A  "missing end quote" error will be raised if the trailing quote is
    missing.  It should be noted that the single quote (apostrophe) has a special  mean-
    ing  in  macro  definitions,  and should be used with care.  The following are legal
    quoted strings:

              "GREAT'STRING'(("
              "X"

    The following are not legal strings:

              "UNBALANCED'

    Note especially that it is not possible to include a quote in a string by  repeating
    it, as in some high level languages.


    _C_o_m_m_e_n_t_s _a_n_d _L_i_n_e _E_n_d_s

         All lines may end with a comment.  Comments begin with a semicolon and may  in-
    clude any text.  Comments are completely ignored in the normal assembly process, but
    they are stored as part of the text of a macro,  and  macro  parameter  substitution
    does apply to them.

              <line end> ::= [ ; { <character> } ] <end of line>

    Note that, unlike their use in high level languages descended from algol, it is con-
    ventional to space the semicolon away from any immediately preceding commands and to
    allign the semicolons on successive lines to make a  column  which  delimits  useful
    text from comments.

                                       _B_A_S_I_C _F_O_R_M_A_T_S

         At the syntactic level, a SMAL 6502 program consists of a  sequence  of  lines,
    each  of  which  may contain any number of labels, an assembly directive, and a com-
    ment.  Each of these fields is optional, and each may begin anywhere on the line, as
    long as they appear in the required order.  Comments are defined at the lexical lev-
    el and so are not formally treated here.

              <program> ::= { <line> } <end of file>
              <line> ::= { <label> } [ <directive> ] <line end>

    Unlike many older assembly languages, these rules allow indenting and blank lines to
    be used to clarify the structure of programs wherever this is convenient.


    _L_a_b_e_l_s

         A label is an indentifier followed by a colon.  The effect of using a  particu-
    lar identifier as a label is that the value of that identifier is set to the current
    assembly location and it becomes illegal to alter that value in any way.   The  ini-
    tial  value  of  the assembly location counter is relocatable zero, and it is incre-
    mented once for each byte assembled.

              <label> ::= <identifier> :

    Any attempt to redefine a label will result in a "multiple label definition"  error.
    If  the  value  of the location counter differs between the two passes of the assem-
    bler, for example, as the result of a macro expanding differently on the two passes,
    a  "label  differed  in pass 1" error will result.  The following are legal lines of
    SMAL code containing labels:

              FIRST:
              ANOTHER :    ;COMMENT
                AGAIN:

    Note the lack of column restrictions and the use  of  optional  spaces  between  the
    identifier and the colon.


    _D_i_r_e_c_t_i_v_e_s

         There are two kinds of assembler directives:  The first takes the  form  of  an
    assignment  statement and is used to assign values to identifiers.  The second takes
    the form of a symbolic directive name or instruction name  followed  by  appropriate
    operands.

              <directive> ::= <assignment> | <symbolic directive>

    The forms of each of the symbolic directives will be documented in  later  sections.
    In  general,  each  begins with an identifier which is either an op-code name or the
    name of some assembly operation.  If an illegal identifier is used in this  context,
    an  "invalid  directive" error will result.  Directive names are not reserved words;
    that is, the name of a directive may be used as a  label  without  any  conflict  of
    meaning.   On systems allowing the use of both upper and lower case, directive names



                                             6





    D. W. Jones                                                                SMAL 6502


    may be in either case.

         The assignment directive assigns the value of an  arbitrary  expression  to  an
    identifier.   An  identifier  assigned a value in this way may be redefined at will,
    but it must not be used elsewhere as a label.

              <assignment> ::= <identifier> = <expression>

    The following lines of legal SMAL code demonstrate the use of assignment:

              NEG1 = -1
              SIXTEENTHOUSAND=8000+8000
              L:     THISLOC = L

    Note that spaces are ignored before and after the equals sign, and that  labels  may
    be  used on the same line as an assignment.  The following lines demonstrate illegal
    assignments:

              MULDEF: MULDEF = 6
              A = B
              B = A

    In the first case, the error is that an identifier used in a  label  cannot  be  as-
    signed to.  In the second and third cases, the definition is circular.

         A special form of the assignment directive  is  used  to  modify  the  location
    counter.  This is used, for example, to set the assembly origin.

              <assignment> ::= . = <expression>

    Here, the special symbol "." (period) is used as if it were an  identifier  standing
    for  the location counter.  The location counter will take on both the magnitude and
    type of the expression.  This means that an absolute assembly section may  be  begun
    by  assigning  an absolute value such as a numeric constant to the location counter,
    and a relocatable section may be begun by assigning an external symbol, common name,
    or  other  relocatable  value  to  the  location  counter.  By default, the location
    counter is initialized to relocatable zero.  The following lines of legal SMAL  6502
    code demonstrate the use of this form:

              BLOCK: .=.+5 ;BLOCK IS A LABEL ON 5 BYTES OF UNINITIALIZED MEMORY
              A = .
              . = COMMON
                    ; CODE TO INITIALIZE LOCATIONS IN COMMON
              . = A

    In the first example above, the location counter is incremented  by  5  bytes.   The
    remainder of the lines demonstrate how the current location can be saved, changed to
    a different area, for example, a location in common, and restored to  where  it  was
    originally.

    _E_x_p_r_e_s_s_i_o_n_s

         Expressions are composed of a sequence of terms separated by binary  operators.
    There is no operator precidence hierarchy, and terms are evaluated and combined in a
    strict left to right order.  If a different order is needed, parentheses may be used
    to construct a term which is itself an expression.

              <expression> ::= <term> { <binary operator> <term> }

    The allowed binary operators are:

              <binary operator> ::= + | -
                                  | > | < | =
                                  | & | !

    These stand for, respectively, the arithmetic operations of  addition  and  subtrac-
    tion,  the  comparison operations greater than, less than, and equal to, the boolean
    operations and and or.  The following lines of legal SMAL 6502 code demonstrate  the
    use of expressions:

              FOUR     =  3 - 2 + 3
              MINUSTWO = 3 - (2 + 3)
              TRUE     = 5 = (3 + 2)
              NONSENSE =   5 = 3+2

    In the final example, the value of "NONSENSE" will not be the same as "TRUE" because
    of  left  to  right evaluation.  Note that spaces (or the lack of spaces) around the
    operators have no effect on the order of evaluation.

         The arithmetic operations are computed using 16 bit binary numbers.  In the ab-
    sence  of  other  constraints,  these  may  be treated as either values in the range
    -32768 to 32767 or as values in the range 0 to 65535.  Overflow  and  underflow  are
    not  detected because it is impossible for the assembler to determine which operands
    were intended to be signed or whether or not the result  should  be  interpreted  as
    signed.   The following rules govern the type of the result when adding or subtract-
    ing values of various types:

                 absolute + absolute    ==> absolute
                 absolute + relocatable ==> relocatable
              relocatable + absolute    ==> relocatable
              relocatable + relocatable ==> error
                 absolute - absolute    ==> absolute
                 absolute - relocatable ==> error
              relocatable - absolute    ==> relocatable
              relocatable - relocatable ==> absolute or error

    Note that, in the last case, the difference of two relocatable values will  only  be
    defined  if  both  are relocated relative to the same relocation base.  A "misuse of
    relocation" error will result whenever an illegal combination of operands is used.

         The comparison operations are computed using 16  bit  signed  two's  complement
    numbers.   Thus,  values  will be interpreted as being in the range -32768 to 32767.
    As a result, the constant 32768 will be reported to be less than the constant 32767.
    The  results of the comparison operations will be -1, 0 and 1, corresponding respec-



                                             8





    D. W. Jones                                                                SMAL 6502


    tively to true, false and incomparable.  It is illegal to  compare  values  of  dif-
    ferent  types; thus, absolute values may only be compared with other absolute values
    and not with relocatable values.  Failure to follow  this  rule  will  result  in  a
    "misuse of relocation" error and a value of 1.

         The boolean and and or operators are computed by applying the  basic  operation
    to  corresponding pairs of bits from the operands to produce each bit of the result.
    Thus, these may be used for bit setting and testing as well as for combining results
    from  comparison  operations  in a boolean expression.  These operations may only be
    applied to absolute values; their application to relocatable values will result in a
    "misuse of relocation" error.


    _T_e_r_m_s

         The terms of an expression consist of an optional unary operatior  preceding  a
    value.   Thus, unary operators may be included before any operand used in an expres-
    sion.

              <term> ::= [ <unary operator> ] <value>
              <unary operator> ::= + | - | \ | ?

    The allowed unary operators are a leading plus sign, a leading minus sign, a leading
    not sign, and a leading question mark for register specification.  The following ex-
    amples demonstrate legal use of terms in SMAL 6502 expressions:

              TRUE = ( +1 = 1 )
              FALSE = \ TRUE
              THREE   = - 3 - - 6
              NEGNINE = -(3 - - 6)

    The last two examples demonstrate that unary operators have a higher precedence than
    binary operators.

         The unary plus operator is always legal and has no  effect  on  the  associated
    value.

         The unary minus operator is used to negate the given value by taking the  two's
    complement.   It  may  only be applied to absolute values; it's use with relocatable
    values will result in a "misuse of relocation" error.

         The unary not operator is used to take the one's complement of the given value.
    As  such,  it  may  be used for bit manipulation or to invert the sense of a boolean
    value resulting, for example, from a comparison operation.   As  with  unary  minus,

    to the result of an illegal comparison, returns a value which is  neither  true  nor
    false.

    As  such, it may only be applied to the absolute values 0 and 1.  Especially in mac-

    as in the following example:

              C = ?(?1-D)

         The values used to compose the terms of expressions may either be simple values
    such  as  identifiers,  numbers, strings, and references to the current value of the

    predefined functions.

              <value> ::= <identifier>
                        | <number>
                        | <quoted string>
                        | .
                        | ( <expression> )
                        | <function>

    When an identifier is used as a value, it must have a value assigned to it somewhere
    in  the program.  Simple forward references are allowed, and are processed using two

    symbol  must have been defined by the end of the first pass for that reference to be
    valid.  References to undefined identifiers will result in an "undefined symbol" er-

    current value of the location counter.  An "unbalanced parentheses"  error  will  be
    raised if the parentheses on an expression do not balance.

    values  of  the characters will be used.  If the string contains only one character,
    it will be stored in the least significant 8 bits of the value.  If the string  con-

    second in the least significant 8 bits.  Unused bits of the value  will  be  set  to
    zero.   An attempt to use a string longer than two characters as a value will result
    in a "value out of bounds" error.

    test  whether  it  is a forward reference, to test the type of an expression, and to
    test the length of a text fragment.

                           | FWD ( <identifier> )
                           | TYP ( <expression> )
                           | LEN ( <balanced string> )
                           | HI  ( <expression> )
                           | LOW ( <expression> )

    Note that the form of the argument lists for these functions depends on the particu-
    lar  function used.  An "invalid function" error will result if any other identifier
    is used in a context where a function name  is  allowed.   Function  names  are  not
    reserved  words;  the  use  of an identifier as a function name is determined by the

    fact that it is followed by a begin parenthesis.

         The DEF function returns true (-1) if its argument has been defined  previously
    in  the  text  of  the program, either as a label or as the object of an assignment.
    Otherwise, if the argument is an identifier which has not been  previously  defined,
    it  returns  false(0).  A "symbolic name expected" error will be raised if the argu-
    ment is not an identifier; in this case, the value returned will be ambiguous  (+1).
    The  following fragment of a SMAL 6502 assembler listing demonstrates the use of the
    DEF function:

              169                  ]DEF = 0
              170 +0091: 00        ] B DEF(UNDEF)
              171 +0092: FF        ] B DEF ( DEF )
              172                  ]UNDEF = 0

    Note that spaces have no effect, and that the DEF function responds  to  whether  or
    not  its  argument was previously defined in the text and thus will return true only
    if it is defined earlier.  Thus, DEF will always have the same  effect  during  both
    passes of the assembler.

    tion, but it returns true when there is an unresolved forward reference to the argu-
    ment.  Thus, FWD will be false before the first reference to the argument and  false
    after  the argument is defined, but true between a reference to the argument and the
    later definition.  The following fragment of a SMAL 6502  assembler  listing  demon-

              172 +0093: 00        ] B FWD(FWD)
              173                  ]REF = FWD
              174 +0094: FF        ] B FWD(FWD)
              175                  ]FWD = 0
              176 +0095: 00        ] B FWD(FWD)

    Note that the use of an identifier as an argument to the DEF or  FWD  function  does
    not  constitute  a  reference  to  that identifier from the point of view of the FWD
    function.

    a  general  rule,  the  particular value returned by TYP will be meaningless, except
    that it will be the same for all values relocated relative to  the  same  relocation
    base.   The  only exception to this rule is that the TYP applied to any absolute ex-
    pression will return zero.  The following fragment of a SMAL 6502 assembler  listing
    demonstrates the use of the TYP function:

              176                  ]  EXT X
              177 +0097: 00        ]L:B TYP(0)
              178 +0098: FF        ]  B TYP(.) = TYP(L)
              179 +0099: 00        ]  B TYP(X) = TYP(L)

    ment to it constitutes a forward reference to that identifier.

         SMAL 6502 supports directives to store bytes, words,  and  strings  in  memory.
    The first two of these directives have the same syntax:

              <symbolic directive> ::= B <expression> { , <expression> }
                                     | W <expression> { , <expression> }

    The B and W directives store, respectively, one byte (8 bits) and one word (16 bits)
    at  the  current  location.   The location counter will be advanced by the number of
    bytes stored after the expression is evaluated, so that,  for  example,  "W ."  will
    store  a  pointer  to  itself.   If  multiple  operands are included, the additional
    operands are treated as if they were processed by a new B or W directive on the next
    line.  If the value of the expression used on the B directive is greater than 255 or
    less than -128, a "value out of bounds" error will be raised.  Note that "B 128" and
    "B -128"  will  store exactly the same value; in the first case, it was probably in-
    tended to be used as an unsigned 8 bit value, in the second case,  it  was  probably
    intended  to be used as a signed 8 bit value.  The following sample assembly listing
    demonstrates the use of the B and W directives for various purposes:

              23 +000F: FF        ]L: B 255
              24 +0010: 00FF      ]   W 255
              25 +0012: FFFF      ]   W 65535
              26 +0014: FF        ]   B 8$377
              27 +0015: F0        ]   B 2$11110000
              28 +0016: 7FFF      ]   W 32$VVV
              29 +0018: 20        ]   B " "
              30 +0019:+000F      ]   W L
              31 +001B:+0010      ]   W L+1
              32 +001D:+001D      ]   W .

    In the above example, the location counter was  relocatable,  as  indicated  by  the
    leading  plus  sign in the location column in the listing.  The values on the last 3
    lines of the listing are relocatable because they  are  derived  from  the  location
    counter.

         Strings of ASCII characters may be stored  using  the  ASCII  directive.   This
    takes a quoted string as an operand.

              <symbolic directive> ::= ASCII <quoted string> { , <expression> }

    Note that the 7 bit ASCII representation of each character in the string  is  stored
    right  justified  in one byte, and that the most significant bit of that byte is set
    to zero.  On the 6502 "ASCII 'ab'" and "W 'ab'" will not store the  same  result  in
    memory because the 6502 stores the least significant byte of a word first in memory,
    like the PDP-11 and unlike the IBM System 360.  The following  fragment  of  a  SMAL
    6502 assembly listing demonstrates the correct use of the ASCII directive:

              63 +003F: 41        ]   ASCII "A"

         SMAL 6502 allows the results of assembling a number of source  programs  to  be
    combined  into  a  single program at run-time by a linkage editor.  Because of this,
    there are two classes of symbols in SMAL, local symbols and global  symbols.   Local
    symbols are defined only within one particular source program, and the same name may
    be used with a different meaning within another.  Global symbols, on the other hand,
    are shared by all programs which are to be linked into one final program.  There are
    two kinds of global symbols:  Those which are defined internally in one program  and
    referenced  in  another,  and those which are not defined in any particular file but
    are expected to be defined by the linker.


    _E_x_t_e_r_n_a_l _D_e_c_l_a_r_a_t_i_o_n_s

         When a symbol defined in one program is to be referenced by another program, it
    must  be  declared  as being external to the program which uses it.  This is done by
    defining that identifier with an external directive:

              <symbolic directive> ::= EXT <identifier> { , <identifier> }

    Identifiers which are declared as external symbols may not be  used  as  labels  and
    they  may  not have values assigned to them; violation of this rule will result in a
    "multiple label definition" error.  Identifiers used in this context must  not  have
    been  previously referenced in the text of the program; a "name used before defined"
    error will result when this rule is violated.  Multiple identifiers may be  declared
    with one EXT directive.

         In addition to relocatable symbols introduced by defining labels  in  terms  of
    relocatable  location  counter values, each external symbol introduces a new reloca-
    tion base relative to which additional symbols may be defined.  Thus, it is legal to
    add  or  subtract  absolute  values  to  or from an external symbol name in order to
    reference adjacent values (if the name is externally defined as a label,  the  adja-
    cent  values will reference adjacent memory locations).  The following fragment of a
    SMAL assembler listing illustrates the use of external declarations:

              140                  ]   EXT EXT
              141                  ]ADR = EXT + 8
              142 +007A:+0000      ]   W EXT
              143 +007C:+0008      ]   W ADR

    Note that the external symbol "EXT" in the above example is  used  as  a  relocation
    base for the symbol "ADR".

    symbol, it must be declared to be accessible by an internal directive:

              <symbolic directive> ::= INT <identifier> { , <identifier> }

    Identifiers declared as internal must be defined somewhere in the  program;  failure
    to  follow this rule will result in an "undefined symbol" error.  Within the program

    where an internal symbol is defined, that symbol may be manipulated as if it were an
    entirely  local  symbol.  The value of that symbol at the end of the second assembly

    by  the linkage editor, that area must be declared to be a common block and its size

              <symbolic directive> ::= COMMON <identifier> , <expression>

    rules.   Thus,  the name must not have been referenced previous to the common direc-

    the  linkage editor is expected to allocate.  This must be either an absolute value,
    in bytes, or it must be relocated relative to the common base; any other  form  will
    result  in  a "misuse of relocation" error.  Generally, the declarations of the same
    common in the different programs linked by the linker should be the same.   If  dif-
    ferent  sizes  are  specified, the first size encountered by the linker will be used
    and later sizes will be ignored.

    use of the COMMON directive:

              227                  ]COMMON COM1,6

              232 +0001: 06        ]B 6

              234                  ]. = LOCSAVE

         SMAL supports structured  conditional  assembly  facilities  which  provide  an
    assembly-time  control  structure  comparable  to the corresponding run-time control
    structures of many high level languages.

              <symbolic directive> ::= IF <expression>
                                     | ELSEIF <expression>
                                     | ELSE
                                     | ENDIF

    The semantics of the conditional directives is best described in terms of condition-
    al  blocks.   A  conditional  block  begins  with an if block and ends with an endif
    directive.  Between the if block and the endif directive, an  optional  sequence  of
    elseif  blocks is allowed, followed by an optional else block.  Each block is headed
    by a specific directive which controls the assembly of  the  following  sequence  of
    lines, including possible nested conditional blocks.

              <conditional block> ::= <if block>
                                    { <elseif block> }
                                    [ <else block> ]
                                      ENDIF
              <if block> ::= IF <expression> <line end> { <line> }
              <elseif block> ::= ELSEIF <expression> <line end> { <line> }
              <else block> ::= ELSE <line end> { <line> }

    The lines within an if or an elseif block are only assembled  if  the  corresponding
    boolean expression evaluated to true (-1).  The lines within an elseif or else block
    will only be assembled if no previous if or elseif  block  within  that  conditional
    block  was  assembled.   No  more than one sub-block within a conditional block will
    ever be assembled.  A "missing endif" error will be raised if an  if  block  is  not
    correctly terminated before the end of a macro, text insertion, or program.

         It is inappropriate to use labels on the if, elseif,  else,  and  endif  direc-
    tives,  but  they are allowed.  If they are used, they will be considered to be part
    of the immediately preceding sequence of lines.  Thus, the label on an elseif direc-
    tive will be processed as if it were part of the previous if or elseif block.

                                       _M_A_C_R_O _A_S_S_E_M_B_L_Y

         The SMAL 6502 macro facilities allow assembly-time control  structures  compar-
    able  to  the procedure structures of many high level languages.  A macro is a named
    block of text which is assembled into the program wherever its name  occurs  in  the
    context  of  a  macro  call.  If a macro is defined as having formal parameters, the
    corresponding actual parameters are substituted for the formal parameters within the
    body of the macro before it is assembled.


    _M_a_c_r_o _D_e_f_i_n_i_t_i_o_n_s

         Each macro definition begins with a macro directive and  ends  with  an  endmac
    directive.   The macro directive is followed by the name of the macro and its formal
    parameter list.

              <symbolic directive> ::= MACRO <identifier> [ <formal list> ]
                                     | ENDMAC

    The semantics of a macro declaration are most easily described  in  terms  of  macro
    blocks  which  begin  with  a macro directive and end with an endmac directive.  The
    body of the block between the two is saved by  the  assembler  and  assembled  as  a
    result of each call to the macro.

              <macro block> ::= MACRO <identifier> [ <formal list> ] <line end>
                              { <line> }
                                ENDMAC

    Note that any labels on the line containing the macro directive are not  interpreted
    as  having anything to do with the macro but are processed as normal labels.  Labels
    on the line containing the endmac directive are  completely  ignored!   If  a  macro
    block  is not properly terminated with an endmac directive, a "missing endmac" error
    will result.  The following fragment of valid SMAL 6502 code illustrates the defini-
    tion of a simple parameterless macro:

              MACRO CRLF
                B #0D
                B #0A
              ENDMAC

    A call to this macro can be used after an ASCII directive to put a CR and  LF  after
    the text string.

         Macro definitions may contain other macro definitions, but the  effect  is  not
    that  of  creating  a  local  macro, as might be expected by anology with high level
    languages.  Instead, the internal macro definition will be processed by  the  assem-
    bler  each time the containing macro is called.  Thus, a macro may be used to create
    a number of other macros by calling it repeatedly with different parameters.









                                             19





    D. W. Jones                                                                SMAL 6502


    _M_a_c_r_o _F_o_r_m_a_l _P_a_r_a_m_e_t_e_r_s

         The formal parameter list on a macro definition lists  the  symbolic  names  of
    each  parameter  and the parameter passing mode.  Symbolic parameter names are iden-
    tifiers.  There is an implementation dependent limit on the number of formal parame-
    ters  allowed;  if  this  is  exceded,  a  "too many macro parameters" error will be
    raised.  Typically, at least 8 parameters will be allowed.

              <formal list> ::= <formal parameter> { , <formal parameter> }
              <formal parameter> ::= <identifier>
                                   | ( <identifier> )
                                   | = <identifier>

    The three macro parameter modes are:  Name mode, in which the  formal  parameter  is
    declared  by  just  its  name; list mode, in which the formal parameter name is sur-
    rounded by parentheses; and value mode, in which the formal parameter name  is  pre-
    ceded  by an equals sign.  The treatment of actual parameters in each of these three
    modes will be discussed later.  The following fragment of a SMAL 6502 assembly list-
    ing illustrates the definition of a simple macro with one parameter passed by name:

              MACRO ASCIICRLF TEXT
                 ASCII TEXT
                 CRLF
              ENDMAC

    Note that the above macro contains a call to the macro "CRLF" defined in the  previ-
    ous example.

         Within the macro body, each occurance of any macro  formal  parameter  name  is
    identified  as  the  macro  is defined.  Formal parameters will be identified within
    comments and within character strings.  The only time that a formal  parameter  will
    not  be  identified  is when it is embedded in a larger identifier.  For example, if
    "A" and "B" are formal parameters, neither of them will be identified in the  string
    "AB".   If  "AB" is to be seen as the concatenation of two parameters, an apostrophe
    should be inserted between the two, as in "A'B".  Within the body of any macro, sin-
    gle  apostrophes  will  be  deleted,  and strings of two or more apostrophes will be
    shortened by one when that macro is defined.  Thus, special care must be taken  when
    using apostrophes as single quotes around quoted strings.



    _M_a_c_r_o _C_a_l_l_s

         A macro call takes the form of a symbolic directive which begins with the  name
    of a previously defined macro, followed by a list of actual parameters.

              <symbolic directive> ::= <identifier> [ <actual list> ]
              <actual list> ::= <actual parameter> { , <actual parameter> }
              <actual parameter> ::= [ <by name> | <by list> | <by value> ]

    The first step in processing a macro call is to store the text of each actual param-
    eter,  according to the parameter passing rules associated with that parameter type.
    Individual parameters may be omitted or blank, in which case, no text is passed.  In
    all  cases, the number of actual parameters must be less than or equal to the number



                                             20





    D. W. Jones                                                                SMAL 6502


    of formal parameters.  After the parameters are stored, assembly of the body of  the
    macro  begins.  As the body is being assembled, all formal parameters which had been
    identified at the time the body was originally defined are replaced with the text of
    the  corresponding  actual parameters.  If the resulting text for any line is longer
    than the implementation defined line length limit, the  error  "text  too  long  for
    line" will result.

         When a formal parameter is declared as a name parameter, the  actual  parameter
    may  be  any  text which does not include commas unless the commas are parenthesized
    and as long as any parentheses in the text are balanced.  The entire text of a  name
    parameter  will  be passed with no changes other than to remove leading and trailing
    blanks.

         When a formal parameter is declared as a list parameter, the  actual  parameter
    must  be enclosed in parentheses and may contain any lexically valid text as long as
    the parentheses it contains are balanced.   A  substring  specification  is  allowed
    after the end parenthesis; this consists of two expressions set off from the parame-
    ter and each other by colons.

              <by list> ::= ( <balanced string> ) [ <substring> ]
              <substring> ::= : [ <expression>  [ :] <expression> ]

    If the substring specification is absent, the entire balanced string will be  passed
    as a parameter.  Note that the enclosing parentheses are never passed.  If the first
    expression in the substring specification is present, it specifies the index of  the
    first  character in the balanced string to be passed (the default value of the first
    expression is one).  If the second expression  in  the  substring  specification  is
    present,  it specifies how many characters from the balanced string are to be passed
    (the default value of the second expression  is  "all").   Substring  specifications
    should  be  used  with  care  because  they  may  introduce  strings with unbalanced
    parentheses.

         When a formal parameter is declared as a value parameter, the actual  parameter
    must be an expression.

              <by value> ::= <expression>

    The expression will be evaluated at the time of the macro call; if the result is  an
    absolute  value, the text of the decimal representation of that value will be passed
    as a parameter.  Note that the decimal representation used will  be  unsigned,  that
    is, -1 will be passed as 65535; this allows identifiers to be constructed by append-
    ing the value of the parameter to a letter.  If the value is not  absolute,  an  ex-
    pression will be passed which evaluates to the desired value.

         In no case will a macro call be executed if any errors are found in the  actual
    parameter  list.   During the assembly of the body of a macro, other macro calls may
    be processed, even recursive calls.

         When the SMAL 6502 assembler processes a SMAL 6502 source program, it  produces
    an  object  file.   SMAL  6502 object files are encoded in the SMAL 6502 object sub-
    language, and may be linked into a load file by the SMAL 6502 assembler.   When  the
    SMAL 6502 assembler is used for this linkage editing function, it is controlled by a
    SMAL 6502 linker control program, encoded in  the  SMAL  6502  linker  control  sub-
    language.   As a linker, the SMAL 6502 assembler may process object library files in
    addition to simple object files; such object library files must be  encoded  in  the
    SMAL  6502  object library sublanguage.  Finally, the output of the SMAL 6502 assem-
    bler when it is used as a linkage editor is either another object  file  or  a  load
    file encoded in the SMAL 6502 loader sublanguage.

         As the terminology suggests, SMAL 6502 object files, linker control files,  and
    load  files  are  all legal SMAL 6502 programs, encoded in particular subsets of the
    language.  SMAL 6502 object files have less symbolic information in them  than  SMAL
    6502  source  files,  and SMAL 6502 load files have almost no symbolic content (what
    remains is concerned only with establishing relocatability).  SMAL 6502 linker  con-
    trol  files and object library files consist primarily of information concerning how
    to find each part of the program to be linked and when to link it.

    names should only be defined by a linker control directive when they are not defined
    by an INT directive in one of the object files to be linked.

    at assembly time, the following linker control may be used:

              <linker control> ::= S<identifier> = <number> <line end>

    When this form is used, it will override the size of the given  common  declared  in
    the  programs being linked.  Thus, it is actually possible to decrease the size of a
    common below that which a program declared that it needed.  When this  is  intended,
    the common itself should probably begin with an external reference which is expected
    to be set by the linker control program to indicate the size of the common  actually
    allocated.

    any of the routines being linked, it may be specified at linkage time as follows:

              <linker control> ::= S R<identifier>

    ror will result if this directive is used and one of the linked routines already has

              <linker control> ::= <identifier> = R<identifier> <line end>

         A SMAL 6502 object library file is a file of references  to  SMAL  6502  object
    code  files.   Library files are textual in form, and may be maintained by a conven-
    tional text editor.  Unlike the approach taken on many other systems, library  files
    do  not  contain object code, but only contain references to object files.  The text
    of the library file itself is written in the SMAL 6502 object library sublanguage.

              <library file> ::= { <object reference> } <end of file>

    Each object reference in a library file specifies the name of an object file and the
    names of one or more symbols which that object file defines:

              <object reference> ::= IF <symbol list> <line end>
                                       USE <quoted string> <line end>
                                     ENDIF <line end>
              <symbol list> ::= <symbol reference> { ! <symbol reference> }
              <symbol reference> ::= FWD ( R<identifier> )

    The effect of an object reference is to cause the SMAL 6502 assembler, when used  as
    a  linker,  to  link the indicated object file if the previously loaded material has
    made any references to the symbols in the symbol list  and  the  referenced  symbols
    have  not been previously defined.  Each symbol in the symbol list takes the form of
    an external name, that is, an identifier consisting of an "R" prefix on an  identif-
    ier used as an operand of a COMMON or INT directive in the object file.  The follow-
    ing is a legal SMAL 6502 library file:

              IF FWD(RSIN) ! FWD(RCOS) ! FWD(RTAN)
                USE "TRIGFUNC"
              ENDIF
              IF FWD(REXP) ! FWD(RPOWER)
                USE "EXPFUNC"
              ENDIF
              IF FWD(RLOG) ! FWD(RLN)
                USE "LOGFUNC"
              ENDIF
              IF FWD(RFLOAT)
                USE "FLOATFUNC"
              ENDIF
              IF FWD(RFIX)
                USE "FIXFUNC"
              ENDIF

    Note that, if one of the object files in the library references another,  that  file
    should  be  placed  before  the  file it relies on.  It is legal to repeat an object
    reference any number of times in an object library file, and it  is  legal  to  have
    multiple  object references with different symbol references which refer to the same
    object file.

    brary should be organized as a single directory, with the library file itself stored
    under that directory in a file name "DIR", and all other object files in the library

    the section on miscellaneious assembly directives, this  will  allow  relative  file

              <load file> ::= R=.<end of line>

                                 end else if ch in ['A'..'F' then begin]
              {precision}             temp := (16 * temp) + (ord(ch) - ord('A')) + 10;
                                 end;

                            {assert ch in ['+','A'..'F','0'..'9']}

                                 read(f,ch) {assert ch='R'};
                                 temp := temp + base;
                            end;

                            read(f,ch) {assert ch='R'};
                            temp := base;
                       end;
                       {assert eoln(f)}

                   while not(eof(f)) do begin

                                       loc := loc + 1;
                                  end;
                             "W": begin

              {precision}              memory[loc + 1 := temp mod] 256;
                                       loc := loc + 2;
                                  end;

         The machine independent version of the SMAL assembler was written to be  easily
    moved to a new machine, but this does not imply that it will run efficiently in that
    environment.  In fact, transportability and efficiency are in direct conflict, espe-
    cially in the areas of bit packing and integer arithmetic.  If efficiency becomes an
    issue, the following steps outline the order in which different changes to  the  as-
    sembler should be made to remove machine independance and speed things up:

         Many Pascal implementations generate a considerable amount  of  code  to  check
    such  things  as  array bounds and subrange variables.  Turning off this checking is
    frequently easy, and has resulted in improvements of about 15% for the  SMAL  assem-
    bler  under the Hull R-mode compiler for the Prime 750 computer.  The SMAL assembler
    is coded to be resiliant enough that turning off the run-time  checking  should  not
    threaten  the  reliability of the assembler, but if any changes are made to the com-
    piler, the checks should be turned back on until all is secure.

         The routine "writehex" used for object code and listing  generation  uses  some
    cumbersome  code  to guarantee consistent results on machines with different integer
    representations.  Since this routine is called three to four times for each line  of
    code  assembled,  it  may  pay to recode it in machine code using shift and mask in-
    structions to extract and convert hexadecimal digits.

         The lexical analysis routine for parsing numeric constants  has  a  significant
    amount  of cumbersome code to allow it to handle unsigned 16 bit values on a machine
    using a signed 16 bit representation.  If the SMAL assembler is  run  on  a  machine
    with a larger word size, this code can be significantly simplified.

         A key cause of inefficiency in the SMAL assembler is the implementation  of  16
    bit  two's  complement  arithmetic  in  a  manner which will run consistently on any
    machine which supports the desired range of integer values.  The routines  responsi-
    ble  for  this are grouped at head of the assembler and may easily be changed to use
    external routines coded in machine code.  On versions of Pascal implemented with  16
    bit  arithmetic,  it  may be sufficient to simply turn off run-time checking and use
    the built in operations; thus, a call to "add(a,b)" may be equivalent to "a+b"  when
    run-time  checking is disabled.  Although this change will have a significant effect
    on the speed of these operations, they are infrequently  used  during  the  assembly
    process,  and probably do not contribute significantly to the time taken to assemble
    typical programs.
